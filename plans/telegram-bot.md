# Фича: Telegram-бот «Орландо-Механик» (вторая «дверь» к тому же движку)

## Цель

Весь функционал PWA — в Telegram: те же кнопки, тот же движок (`lib/ask.ts`, `lib/diagnose.ts`, `lib/summarize.ts`, `lib/car.ts`, `lib/parse-record.ts`). PWA остаётся как запасной путь и для друзей. Главный выигрыш — голос: зажал микрофон в чате и отправил звук мотора в Диагност.

## Решения (приняты 2026-10-02)

- Имя: «Орландо-Механик», ник `@OrlandoMechanic_bot` (первый вариант `@OrlandoMech_bot` оказался занят).
- Хостинг: Vercel, webhook (`app/api/telegram/route.ts`). Vercel за границей — прокси к api.telegram.org не нужен. Мини-ПК и туннель не используем.
- Без библиотек: чистый fetch к Bot API (~100 строк). Перед кодом — глянуть, нет ли готового Vercel-примера (правило «GitHub сначала»); если готовое проще — берём.
- Кнопки: инлайн-«гармошка» (решение владельца 2026-10-02). Под сообщением одна кнопка «☰ Меню»; нажал — на месте раскрывается блок из 6 кнопок (editMessageReplyMarkup); нажал любую — блок схлопывается обратно в «☰ Меню» и бот сразу спрашивает, что нужно. Нижняя постоянная клавиатура не используется, чат остаётся чистым. «☰ Меню» висит под каждым ответом бота + команда `/menu` + синяя кнопка Menu у поля ввода (setMyCommands) — меню всегда под рукой, как бы далеко ни улетела переписка.
- Оформление: «богатые сообщения» Telegram (Bot API 10.1+, метод `sendRichMessage`, поле `rich_message.markdown`; заголовки, таблицы, списки, цитаты, сворачиваемые `<details>`). Ответы, диагноз, поиск, «Моя машина», «Записи», превью записи — богатые; короткие подсказки с force_reply и подтверждения — обычным текстом. Запасной путь: если Telegram отверг rich-формат — плоский текст; отключатель `TELEGRAM_RICH=0`. У входящего rich-сообщения нет поля `text`, текст достаётся из `rich_message.blocks` (`plainOf` в `lib/tgrich.ts`) — формат ответа на rich-сообщение проверить вживую.
- Состояние гармошки хранить не надо: развёрнута она или свёрнута — это просто разметка кнопок на самом сообщении.
- Доступ: числовой id хозяина в env `TELEGRAM_OWNER_ID` (надёжнее «первый /start»: нет гонки за публичный ник), остальным — отказ. Секрет вебхука `TELEGRAM_WEBHOOK_SECRET` отсекает чужие запросы. Без базы: id узнаём один раз через getUpdates.
- Режим диалога без базы: подсказка бота отправляется с force_reply, а по тексту сообщения, на которое ты ответил (`reply_to_message`), бот понимает режим. Таблица `bot_state` в Фазе 1 не нужна; вернёмся к ней в Фазе 2, если подтверждение записи не поместится в кнопки.
- Запись в сервисную книжку — только хозяин + превью/подтверждение, как в PWA (PIN-логика заменяется chat_id хозяина).

## Скоуп MVP

**Входит:** инлайн-меню-гармошка (💬 Спросить · 📝 Суммировать · 🩺 Диагност · ✍️ Записать работу · 🛠 Моя машина · 📋 Записи), ответы с разбивкой по 4096 символов, подтверждение записи кнопками, голос → Диагност, выгрузка CSV/JSON файлом.

**НЕ входит:** мульти-пользователи и аккаунты (для друзей — auto-book), «Спросить в интернете» (убрана и из PWA).

**Правка и удаление записей — входят в Фазу 2** (решение владельца 2026-10-02: «а чего не сделаешь? security review проведёшь потом»). Защита: только `TELEGRAM_OWNER_ID`; удаление — через второе подтверждение; id записи из кнопки проверяется как UUID; правка идёт через то же превью «было → стало» + ✓/✗, что и новая запись. Security review — сразу после Фазы 2.

## Фазы

### Фаза 1: Каркас + чтение ✅
**Цель:** бот отвечает только хозяину; работают «Спросить», «Суммировать», «Моя машина», «Записи».
**Файлы:** `app/api/telegram/route.ts`, `lib/telegram.ts` (sendMessage, split по 4096, инлайн-клавиатуры, answerCallbackQuery, editMessageReplyMarkup — раскрыть/схлопнуть гармошку), таблица `bot_state(chat_id, role, mode, payload)` в Supabase (SQL — отдельным файлом в `supabase/`).
**Критерий:** webhook проверяет секретный заголовок Telegram; чужой chat_id получает отказ; кнопка «Спросить» → вопрос → ответ с теми же источниками, что в PWA.
**Промт:** «Фаза 1 из plans/telegram-bot.md: webhook-роут, lib/telegram.ts, bot_state, четыре кнопки чтения. Прогони локально имитацией апдейтов (curl с JSON), потом проверь на проде, почини что упало.»

### Фаза 2: Диагност, запись работы, правка и удаление ✅ (+ «Поиск по чату», богатое оформление)
**Цель:** «Диагност» текстом (светофор, причины; уточнение — ответом на сообщение бота, исходный симптом берётся из эха в первой строке); «Записать работу» с превью + ✓ Сохранить / ✗ Отмена; из «Записи» — ✏️ исправить (правка словами → превью → ✓/✗) и 🗑 удалить (с подтверждением).
**Файлы:** `lib/bot.ts`, `lib/bot-pending.ts` (черновики в таблице `bot_pending`, атомарное «взять и удалить» = защита от двойного нажатия), `lib/parse-record.ts` (+`applyEdit`), `supabase/migrations/*_bot_pending.sql` (владелец выполняет в SQL Editor).
**Критерий:** превью не пишет в БД до нажатия «Сохранить»; запись видна в PWA; двойное нажатие «Сохранить» не создаёт дубль; удаление требует второго подтверждения.

### Фаза 3: Голос и файлы ✅
**Цель:** голосовое сообщение → Диагност; выгрузка CSV/JSON документом.
**Итог 2026-10-02:** конвертация не понадобилась — Gemini 2.5 Flash через OpenRouter принимает OGG/Opus как есть (проверено на синтетическом стуке, формат `ogg` и `opus`). Голос скачивается через `getFile` (`httpGetBinary`), лимиты: до 60 сек и 2 МБ. Выгрузка — `sendDocument` по публичной ссылке на `/api/export`. Проверено на живом сайте: голос, выгрузка, запись/правка/отмена/удаление/двойное нажатие.
**Критерий:** голосовое с реальным звуком мотора даёт описание звука и триаж.

### Фаза 4: Сверка ✅ (security review чистый; сверка с PWA пройдена; вебхук установлен, переменные в Vercel)
Security review (публичный адрес webhook: секретный заголовок, whitelist chat_id, лимиты), README, плана-прогноз vs факт на реальной машине.

## Риски

- Telegram у владельца работает через VPN: бот доступен ровно настолько, насколько доступен сам Telegram. PWA — запасной путь.
- Публичный ник: без whitelist любой потратит наши токены нейросетей.
- Serverless без памяти: режим диалога и ожидающая запись живут в `bot_state`.
- Лимит Vercel 60 сек на ответ: Диагност укладывается (10–20 сек), голос с конвертацией — проверить.
